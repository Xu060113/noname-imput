## 1. 术语

| 术语 | 含义 |
|---|---|
| 上屏 | 输入法自己写进文本框的文字：拼音选中的汉字、英文按 Enter 上屏的单词、按 Tab 或数字键接受的 AI 候选词。粘贴不算 |
| 当前句 | 光标前、从上一个句末标点（`。！？.!?`）或换行之后到光标为止的文字。判断中英文和发给 AI 的问题，都只看这一段 |
| 中文句 / 英文句 | 当前句里只要有一个汉字就算中文句；没有汉字的就是英文句 |
| 文件模式 | 发给 DeepSeek 的请求里带上全部课程文件的文字，让 AI 依据文件回答 |
| 知识文件 | 预处理后得到的一个文本文件，里面是全部 PDF 抽出的文字，带「文件名 第几页」标记 |
| token | 模型计算长度和费用的单位。英文大约 1 个单词 1.3 个 token |
| 缓存命中 | DeepSeek 发现这次请求的开头和之前某次一模一样，就复用之前的计算，这部分输入按 1/50 的价格收费，速度也更快 |
| TSF | Windows 的文字服务框架，输入法通过它读写文本框里的文字 |

## 4. 实施步骤

### 阶段 0：测速（先验证最大风险）

**为什么先做**：带文件后如果太慢，后面的工作都白做。这一步只写一个独立脚本，不碰输入法。

1. 我新建 `Scripts/test_knowledge_latency.py`。它按输入法将来的请求格式，连续发 3 次请求：
   - 第 1 次：问 `What is phishing?`，这时缓存为空（冷启动）；
   - 第 2 次：同一个问题再问一次（应该命中缓存）；
   - 第 3 次：换一个问题 `What is social engineering?`（文件部分相同，也应该命中缓存）。
2. 每次输出：第一个候选出来的时间、全部完成的时间、缓存命中和未命中的 token 数、AI 的回答。
3. **由你在自己的终端里运行**。API Key 由你自己在终端里设成环境变量，不经过我：
   ```powershell
   $env:DEEPSEEK_API_KEY = "你的密钥"
   uv run --with pymupdf python -X utf8 Scripts/test_knowledge_latency.py
   ```
4. 费用约 $0.03（1 次未命中加 2 次命中）。
5. **通过标准**：命中缓存时，第一个候选在 **3 秒**内出来（见第 7 节第 1 项，待你确认）；两个问题都答对，而且答案和文件内容一致。
6. **不通过怎么办**：我说明慢在哪里，再给你备选方案，比如先在本地用关键词粗筛文件再发，或者只发 Tutorial 部分。你确认后再继续。
